# 桌面代理与私聊候选验证门禁

本用例只在下一次明确获准测试发布、候选兼容验证通过后执行。本轮不执行部署、重新打包或现场验收。
复用 [公共验收规则](acceptance.md) 的编号、完整性、重复、顺序、身份与清理要求。
Windows 原生结果必须在 Windows 记录，macOS 上设置 TargetPlatform.windows 的 widget 仅证明布局。

## 候选与兼容

记录服务端、App、Core 的提交/制品摘要、系统版本及 CPU 架构。先完成新/旧服务端与客户端、Legacy/V2/V3
协商组合。P5 现代通知必须同时具有合法 method/params/schema；旧 P5 hint 只唤醒可靠接收，不能直接解密或 ACK。
验证 P6 的原 delivery-context、group.incoming、notice 行为未变；重复/乱序提示、拉取中再次提示、重连/回前台均须恰好投影一次。

## 原生网络矩阵

分别在 macOS 和 Windows 运行以下组合。操作前保存系统代理配置，结束精确恢复，不记录代理密码或业务凭据。

| 场景 | 必须观察 |
| --- | --- |
| 无代理、静态 HTTP/HTTPS、SOCKS5 | 新请求路径、证书验证、HTTP/WS/头像/附件均可用 |
| PAC、例外规则、系统已启用自动配置 | 命中与绕过均正确，不主动开启自动发现 |
| 端口关闭、连接后卡住、407 或不支持认证 | 仅连接探测不含业务头/体，直连可用时回退，30 秒冷却覆盖多来源 |
| 直连不可用、代理可用 | 仍通过代理完成，不能把首次直连失败当账号失效 |
| HTTP 可用、WS 不可用 | WS Upgrade 受控重连/受限只读换路，随后立即补拉 |
| 开关切换、修改系统代理、VPN/TUN、网络切换 | 新请求及时采用新策略，已提交请求完成，账号与身份不重建 |
| 关闭应用代理但保留环境变量代理 | 应用明确直连；VPN/TUN 路由仍正常 |
| 服务端接受后丢失响应 | 消息按固定 ID/密文恢复，无重复；注册/OTP 不透明重发 |

Windows 的当前用户静态设置、PAC、例外、网络变化和 WS 重连均须保留原生证据。交叉编译不能替代。

### PR review 精确回归边界

- 关闭代理开关，系统代理仍可用；让直连 TCP/TLS 成功后 Upgrade 返回 5xx、断开或超时。
  必须保留直连错误/重连语义，代理不能收到新的 CONNECT 或带认证的 Upgrade；401/403 不触发换路。
- 在代理探测及 WS 握手过程中关闭开关，过期探测不能写回路径缓存，旧路径握手不能冒用新的网络代次。
- 分别让 WS 空闲、持续接收消息、持续接收 Ping/Pong，再切换开关/系统代理配置。
  记录代次变化、受控重连和立即补拉；不能用页面“直接连接”文案代替真实连接证据。
  Core 默认的 250ms 读取取消不能重置系统配置检查的截止时间。
- 在既有可丢弃恢复群场景中，只给空闲群主一条合法恢复提示；观察 Core 主动开始权威读取/修复，
  不等待 30 秒前台补拉，也不先点击手工修复。补测处理中再提示、退避期间重复提示及重启续跑。
  非群主、缺原设备状态或冻结设备撤销仍停止；控制提示不能产生聊天投影或 P6 ACK。

这些是新候选的执行门禁；源码测试与本清单不能代替真机结果。

## 双方前台与多设备

复用本次手机与电脑；普通与显式加密私聊分别测试首次会话、五条连续消息、反向回复、多设备同步、
自己的设备离线/慢响应、单副本失败、进程重启。不能为通过测试把普通私聊默认升级为加密。
确认对方副本先开始，同设备有序；自己的慢设备可使原合同仍报告部分失败，但不得阻挡对方首发。
首次消息界面在本地提交后出现，不等待确认 HTTP；确认失败后从持久队列继续。

为每条样本保存脱敏分段：send.prepare、各设备 HTTP/投递、notification.received、同步调度、HTTP 收取、
local_claim、processing_complete、ui_notification。按 UTC 时间与不透明操作摘要关联，不保存正文或认证信息。
连续私聊通常 3–5 秒、首次 5–10 秒只是待实测目标。任何超过十秒的前台样本必须有分段解释；
未解释长样本、遗漏阶段、只看到最终到齐均不能签性能通过。
