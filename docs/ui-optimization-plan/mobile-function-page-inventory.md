# AWiki Me 移动端功能页面全量清单

> 采集日期：2026-08-01
> 真机：P0110（Android，1264 × 2800）
> 范围：当前仓库移动端可见页面、弹窗、底部菜单与关键状态；桌面专属工作区不计入本轮移动端统一设计。

## 1. 结论

- 当前移动端共梳理出 **81 个页面 / 关键状态单元**。
- 本轮真机采集并人工检查了 **27 张有效截图**；其余条件页面均由当前源码入口、文案或状态分支确认。
- 采集过程未退出账号、未清除数据、未提交任何表单，也未修改产品代码。
- 3 类页面因为会生成或导出敏感凭证，不保留截图：身份凭证导出、Skill Agent 一次性安装指令、Daemon 一次性安装命令。
- 当前最容易在统一设计时遗漏的区域，不是核心 7 屏，而是 **多设备加入 / 审批、Agent Inbox、Daemon 生命周期、群成员管理、消息异常与恢复、租户管理**。

## 5. 当前视觉与交互问题

### P1：统一设计前必须解决

1. **长 Handle / DID 的适配没有统一策略。** 联系人资料、智能体会话标题、智能体信息均出现重度截断；有的双行、有的单行省略、有的挤压主按钮。
2. **智能体资料页标题仍显示“用户信息”。** 页面内已经识别为“智能体”，标题语义却没有同步。
3. **二级页面仍混用两套视觉语言。** 核心页已进入 Quiet List 风格，但群组、设备、个人助理、身份匹配弹窗仍保留旧式大卡片 / 高密度表单。
4. **全屏页、底部 Sheet、居中 Dialog 的容器与按钮规格不统一。** 创建群、加入群、编辑资料、身份匹配、语言与确认框需要统一圆角、边距、标题基线和主次按钮。
5. **权限与危险操作缺少一致的层级。** 关注、删除本地记录、退出、删除凭证、移除成员、删除 Daemon 目前分散在不同颜色和容器结构中。

### P2：统一设计时一起收口

1. 智能体空态重心偏低，页面信息密度不足；安装 Daemon 的入口与更多操作关系不清晰。
2. 群详情页的成员操作按钮在普通成员身份下仍占据显著空间，应明确“无权限”而不是像失效控件。
3. 联系人主页“我关注的 / 关注我的”在数据量较少时留白过多，信息层级偏散。
4. 设备与个人助理页使用较长说明文案，缺少摘要—详情的渐进披露。
5. Android 文件选择器属于系统 UI，只需要保证入口、返回与选择后的 AWiki Me 附件态协调，不应重新绘制系统页。

## 6. 统一设计顺序

1. **A：消息与身份详情** — 消息列表、三类会话、用户 / 智能体 / 群信息、附件与异常状态。
2. **B：联系人与群组** — 联系人首页、关系列表、身份匹配、群列表、群详情与成员管理。
3. **C：智能体与 Daemon** — 列表、详情、创建 Runtime、安装、升级、个人助理与 Agent Inbox。
4. **D：我的、设置、设备与登录** — 我的、资料编辑、设置、安全、多设备、租户与登录注册。

每一批都遵循同一流程：**真机 / 源码证据 → ImageGen 视觉目标 → 选定稿反推组件与页面 → 真机对比微调**。敏感凭证页只用脱敏结构稿，不把真实令牌或导出内容送入设计资产。
