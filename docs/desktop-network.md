# 桌面系统代理与私聊同步

macOS/Windows 的“设置 → 应用 → 网络”只有“使用系统代理”一个开关，默认开启。
说明为“优先使用系统代理，不可用时尝试直接连接。”登录前的网络入口打开同一页面。
窗口收窄后也保留入口；Android/iOS/Web 不展示此设置。

偏好保存在本机应用支持目录的 `awiki_me_network_preferences.json`，独立于账号、Storage Scope
和租户同步。启动与 native Core 打开前恢复选项，保存失败回滚当前传输策略。
关闭时禁止应用层环境变量代理；VPN/TUN 仍由操作系统路由。
页面状态只显示最近路径：系统代理、直接连接、代理不可用已回退。

Rust `NetworkRuntime` 统一处理 Core HTTP/WS、附件、Dart 服务适配和头像下载。
Dart 继续拥有 User Service 协议及逐请求认证；Core 继续拥有 WBA、可靠接收、密码状态与 outbox。
固定 DNS/IP 的匿名发现保留专用安全路径。Windows 保留原 Mozilla CA 文件与摘要校验，
不添加手工代理、密码输入或企业认证界面。原始响应使用分块读取和取消能力，保留头像校验、
重定向安全边界、下载大小/时限及附件流式合同。

实时通知只触发可靠同步，不是消息事实源。同步中的重复提示合并为下一轮，断线、回前台、
周期补拉保留。P5 首次解密提交后直接通知界面，确认发送由既有持久队列立即唤醒，失败和重启
仍按同一 operation 与固定密文恢复。多设备发送优先对方，四路上限，部分失败不呈现为全部成功。

本轮不打包、不发布、不部署。源码检查不代表 Windows 原生代理/PAC/网络变化验证，也不代表
手机与电脑现场延迟已达到连续 3–5 秒、首次 5–10 秒。候选兼容矩阵、现场门禁和命令结果见
[源码验证记录](../../awiki-cli-rs2/docs/verification/20261023-private-chat-network.md)。
